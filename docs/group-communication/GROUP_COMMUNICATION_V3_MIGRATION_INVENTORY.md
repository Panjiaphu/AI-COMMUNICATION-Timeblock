## Key rules

- Native identifiers use opaque UUIDs generated by AI-COMMUNICATION.
- Timeblock principal/workspace identifiers are external identity claims, not
  foreign keys into a Timeblock database.
- Every membership-scoped unique/index constraint includes `space_id`.
- Message ordering uses a monotonically increasing per-space sequence.
- Idempotency keys bind endpoint, actor and payload hash.
- Attachment records store metadata and storage keys, never raw secrets.
- Translation persists FINAL text only and records target language once per
  distinct language.
- Radio bursts record floor release time before downstream processing state.

## Legacy data strategy

V3 begins with a new native Group namespace. Existing Timeblock Group data is
left read-only in Timeblock and is not automatically copied or dual-written.
A future migration requires a separately approved export/import specification,
row-count evidence, attachment transfer plan, idempotent import keys and
rollback proof.

## Required migration behavior

- Add a coherent SQLAlchemy model/session layer and repair Alembic metadata.
- Add one V3 revision whose downgrade drops only V3 tables in reverse
  dependency order.
- Support local SQLite for disposable QA and PostgreSQL for production.
- Production startup must not silently create schema; it must fail readiness
  when the configured database is unavailable or behind the required revision.
